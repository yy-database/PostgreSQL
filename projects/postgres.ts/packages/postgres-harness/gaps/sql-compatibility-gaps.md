Generated by `projects/postgres.ts/packages/postgres-harness/scripts/sql-diff.mjs --seed 20261106`.
Expectations are read from PGlite 0.5.15 through `execProtocolRaw` with an independent
protocol decoder. The `extended` cluster is answered by the `pg` driver over a real
Parse/Bind/Execute/Sync session against a separate PGlite socket. The repository side
is the installed client from `../../..`, so this repository is never its
own reference.

## Differences found

### extended/params-missing

- statement: `SELECT $1::int AS n`
- this repository: `{"error":"08P01: bind message supplies 0 parameters, but prepared statement \"\" requires 1"}`
- PGlite: `{"error":"42P02: there is no parameter $1","results":[],"raw":null}`
- classification: `oracle-limitation` — `pg` sends an empty `values` array as a simple query, so the oracle never reaches `Bind` for this case. PostgreSQL rejects a `Bind` that supplies fewer parameters than the prepared statement requires with `08P01` (`ERRCODE_PROTOCOL_VIOLATION`), which is the reply this repository returns.
- smallest repro: `node projects/postgres.ts/packages/postgres-harness/scripts/sql-diff.mjs --seed 20261106 --only params-missing`

## Client-surface gaps

Each row compares the observable reply of this client with the same reply read from
PGlite through `execProtocolRaw`. A row is `fixed` only when the field order and the
payload bytes match.

### notice-surfaced — fixed

- surface: NoticeResponse
- statement: `DROP TABLE IF EXISTS gap_probe_missing`
- before the fix: NoticeResponse was read off the socket and dropped, so NOTICE and WARNING text never reached the caller.

### partial-results-kept — fixed

- surface: multi-statement error
- statement: `SELECT 1 AS a; SELECT 1 / 0`
